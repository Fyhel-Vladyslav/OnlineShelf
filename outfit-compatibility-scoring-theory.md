# Контекст: Smart Outfit Recommender — теорія попарної оцінки сумісності айтемів

## Проєкт (коротко)
Магістерська робота «Інтелектуальний сервіс формування та візуалізації рекомендацій гардероба (Smart Outfit Recommender)». Мікросервісна архітектура на .NET (ASP.NET Core / FastEndpoints) з Ocelot API Gateway: Image Service, Parse Image Service (vision-класифікатор атрибутів одягу), Shelfs Service (CRUD гардероба, REST+gRPC), Outfit Offer Service (у розробці — підбір і оцінка комбінацій).

Модель айтема (`WardrobeItemDto`): Id, Name, ShelfId, BigImage, AttributeColorMain, AttributeColorSecond, AttributeType, AttributeSeason, AttributePattern, AttributeMatterial, IsFavorite.

Обраний напрям для скорера сумісності (`IOutfitScorer`): **графова нейронна мережа (GNN)**, що узагальнює попарну оцінку сумісності на рівень цілого образу.

---

## Проблема: чому не можна просто рахувати схожість ембедингів

Compatibility ≠ similarity. Якщо натренувати ембединг тільки на загальну візуальну/семантичну схожість (наприклад, звичайний CLIP), дві майже ідентичні речі матимуть високу схожість — але це означає їхню **взаємозамінність**, а не **поєднуваність** в образі. Потрібен окремий, спеціально навчений механізм, що розрізняє ці два відношення.

## Пайплайн ознак айтема (нагадування з попереднього кроку)

- Категоріальна частина: learned embedding-таблиці для AttributeType/Color/Season/Pattern/Matterial → конкатенація.
- Візуальна частина: BigImage → заморожений vision-енкодер (CLIP ViT / FashionCLIP) → вектор.
- Обидві частини → проєкція в спільний embedding `x_i`, рахується один раз у Parse Image Service і кешується (не перераховується на кожен запит).

## Механізм попарної оцінки: Type-Aware / Subspace Attention

Базується на: Vasileva et al., «Learning Type-Aware Embeddings for Fashion Compatibility», ECCV 2018 → розвинуто в CSA-Net (Lin et al., «Fashion Outfit Complementary Item Retrieval», CVPR 2020).

1. **Загальний ембединг** айтема `x_i ∈ R^d` (наприклад, d=64).
2. **Набір навчених масок підпростору** `m_1, ..., m_k ∈ R^d` — елементні фільтри, кожен акцентує різні виміри ембединга (модель сама знаходить смисли: колір, силует, формальність тощо).
3. **Увага, залежна від пари категорій** `(c_i, c_j)`: `ω = softmax(f(c_i, c_j))` — які підпростори важливі саме для цієї пари типів (верх-низ ≠ взуття-сумка).
4. **Проєкція в підпростір, специфічний для пари**:
   `p_i^(c_i,c_j) = Σ_t ω_t · (m_t ⊙ x_i)`
   Той самий айтем проєктується по-різному залежно від того, з яким типом його порівнюють.
5. **Скор сумісності = відстань у цьому підпросторі**:
   `S(i,j) = -‖p_i^(c_i,c_j) − p_j^(c_i,c_j)‖₂` (або косинусна схожість).

## Тренування

- **Позитивні пари**: айтеми, що співіснують в реальному образі (дизайнерський датасет / Polyvore Outfits для попереднього тренування).
- **Негативні пари**: заміна одного айтема на випадковий **того самого типу** — важливо, інакше модель вивчить просто розрізняти категорії, а не сумісність.
- **Triplet margin loss**: `L = max(0, S_negative − S_positive + margin)`.

## Альтернатива метриці: пряма навчена функція

Замість припущення «сумісність = близькість» можна навчити довільну взаємодію:
- MLP: `S(i,j) = MLP([p_i; p_j; p_i − p_j; p_i ⊙ p_j])`
- Білінійна форма: `S(i,j) = p_i^T · W_(c_i,c_j) · p_j`

Дешевша за даними — метрика; гнучкіша — MLP/білінійна форма.

## Агрегація попарних S(i,j) у скор всього образу

Початкова формула проєкту `S = (Σ w_i x_i) · Π C_j` вже відповідає дослідницькій практиці:
- Зважена сума попарних скорів (вага `w` за важливістю пари категорій).
- Мультиплікативний штраф `Π C_j` = принцип «найслабшої ланки»: одна явно несумісна пара (C_j → 0) обвалює весь скор, навіть якщо решта ідеальні. Узгоджується з тим, як людина сприймає образ.

## Обраний напрям: GNN для агрегації

Замість ручного визначення ваг `w_i` для кожної пари категорій — доручити це графовій нейромережі:
- Кожен айтем образу = вузол графа.
- Ребра = попарні `S(i,j)`.
- Message-passing по графу (GNN) сам навчається, наскільки сильно кожна пара впливає на фінальний скор образу.
- Джерело: Cui et al., «Dressing as a Whole: Outfit Compatibility Learning Based on Node-wise Graph Neural Networks», 2019 (в літературі часто NGNN).
- Компроміс: потребує суттєво більше даних для тренування порівняно з явною формулою агрегації — варто заздалегідь спланувати pretraining на Polyvore Outfits перед fine-tune на власному (дизайнерському) датасеті.

## Лінія цитувань для розділу «Огляд літератури»

1. Veit et al., 2015 — Siamese-мережі, спільний style space (базова ідея metric learning для сумісності).
2. Vasileva et al., ECCV 2018 — Type-Aware Embeddings (типо-специфічні підпростори).
3. Lin et al., CVPR 2020 — CSA-Net, category-based subspace attention (масштабований механізм масок + уваги, описаний вище).
4. Cui et al., 2019 — NGNN, граф-based агрегація сумісності цілого образу (обраний напрям).

Усі мають публічний код і оцінюються на датасеті **Polyvore Outfits**, придатному для попереднього тренування перед fine-tune на дизайнерському датасеті проєкту.
